# Установка без скрытых шагов

Нужны два размещения: статический интерфейс на GitHub Pages и API на Cloudflare Workers. D1 хранит работы класса; Workers AI нужен только для AI-подсказок.

## 1. Создайте D1

В Cloudflare Dashboard откройте **Workers & Pages → D1 SQL Database → Create** и создайте базу `hero360-class`.

Скопируйте `worker/wrangler.toml.example` как `worker/wrangler.toml` и вставьте настоящий `database_id`.

Примените схему из папки `worker`:

```bash
npx wrangler d1 execute hero360-class --remote --file=schema.sql
```

Схема создаёт записи У01–У11 без рабочих паролей. Коды появятся только после их установки учителем.

## 2. Создайте секреты Worker

Откройте локально `scripts/hash-password.html`, придумайте пароль не короче 12 символов и получите:

- `TEACHER_PASSWORD_SALT`;
- `TEACHER_PASSWORD_HASH`.

Добавьте их как **секреты**, а не обычные переменные:

```bash
npx wrangler secret put TEACHER_PASSWORD_SALT
npx wrangler secret put TEACHER_PASSWORD_HASH
npx wrangler secret put SESSION_SECRET
npx wrangler secret put STUDENT_CODE_PEPPER
```

Для `SESSION_SECRET` и `STUDENT_CODE_PEPPER` используйте разные случайные строки не короче 32 символов. Не записывайте их в GitHub.

## 3. Ограничьте домен сайта

В `worker/wrangler.toml` замените:

```toml
ALLOWED_ORIGINS = "https://YOUR-GITHUB-USER.github.io"
```

на точный origin сайта. Если используется пользовательский домен, укажите его. Несколько origin разделяются запятыми.

## 4. Подключите Workers AI

В `wrangler.toml` уже есть binding:

```toml
[ai]
binding = "AI"
```

Если Workers AI не подключать, авторизация, библиотека, задания, сохранение и проверка работ продолжат работать; только кнопки AI-подсказок вернут понятную ошибку.

## 5. Опубликуйте Worker

Из папки `worker`:

```bash
npx wrangler deploy
```

Скопируйте выданный адрес вида `https://hero360-api....workers.dev`.

## 6. Подключите интерфейс

В `js/config.js` замените:

```js
API_BASE: "https://YOUR-WORKER.workers.dev"
```

на фактический адрес Worker без завершающего `/`.

## 7. Опубликуйте GitHub Pages

Создайте новый репозиторий и загрузите содержимое папки проекта в его корень. Не загружайте `worker/wrangler.toml`, если в нём есть чувствительные значения; используйте только пример и secrets Cloudflare.

В GitHub откройте **Settings → Pages → Deploy from a branch → main / root → Save**.

Если URL Pages отличается от origin, внесённого в `ALLOWED_ORIGINS`, обновите переменную Worker и выполните `npx wrangler deploy` ещё раз.

## 8. Первый вход

1. Откройте сайт.
2. Выберите **Учитель**.
3. Логин уже зафиксирован: `laila.teacher`.
4. Введите пароль, хеш которого добавлен в secrets.
5. Откройте **Коды учеников** и задайте отдельный временный код для У01–У11.
6. Передайте каждый код только соответствующему ученику.

Смена ученического кода автоматически аннулирует старую сессию этого ученика. Для немедленной смены всех учительских сессий обновите `SESSION_SECRET` и снова разверните Worker.

## 9. Проверка перед работой с классом

- Войдите как учитель и как тестовый ученик в разных приватных окнах.
- Назначьте одно произведение тестовому ученику.
- Сохраните первоначальный и исправленный ответы.
- Убедитесь, что учитель видит обе версии и может поставить пять оценок 0–2.
- Проверьте, что неверный пароль/код не открывает кабинет.
- Не храните ФИО детей: используйте У01–У11.

## Важные ограничения

- AI-реконструкция не является словами автора или персонажа и должна проверяться по фрагменту.
- AI не выставляет итоговую оценку и не определяет способности ребёнка.
- Диаграммы и счётчики строятся только по сохранённым работам и проверкам.
- Перед обработкой реальных данных школа должна проверить соответствие локальным требованиям по защите персональных данных.
